# LAUNCH-01 — archive integrity and multi-track MIDI browser acceptance

**Date:** 2026-10-14 · **Scope:** real Chromium, actual production MusicXML/MXL and MIDI readers, generated adversarial cases. **No human pianists, physical MIDI device or audible speaker test involved.**

## What was fixed

Play Along's native [MXL reader](../src/legacy/parts/140-library-musicxml.js) no longer trusts inconsistent ZIP metadata. The accepted ZIP structure must have a valid end-of-central-directory marker/comment size, a bounded single-disk directory, at most 500 unique entries, exactly bounded directory records, safe relative filenames, an accessible and matching local header, matching compression method, and exactly the declared number of uncompressed bytes. Unsupported encrypted or split archives are refused.

A `META-INF/container.xml` rootfile reference must resolve to an actual matching entry; a corrupt or externally declared missing rootfile may not silently fall back to some other XML. Unsupported XML entity declarations in `container.xml` are rejected, as are non-UTF-8 entry bytes. Both standard ZIP DEFLATE and uncompressed (`method=0`) entries remain supported. Streamed ZIP decompression retains the original 15 MiB **expanded** content limit; input archive size remains limited to 16 MiB.

These guards concern **source integrity and parser robustness**, not a guarantee that any imported score is musically correct. The engine does not claim support for encrypted ZIP, multidisk ZIP, arbitrary `DOCTYPE` or all possible malformed archives.

All ZIP and MIDI test fixtures are assembled in memory by the test from elementary synthetic notes. **No external copyrighted music data is redistributed.** This focused test joins earlier original-source Chromium QA on 1,607 Bach/Schubert notes and real 22-note Pyodide Apply/Export QA; it does **not** duplicate those results or pretend hardware MIDI was exercised.

## Release checklist remaining

- Input boundary coverage is substantially improved, but continue tests on very large permissible files, complex MusicXML navigation/repeats/grace notes, MXL archives generated by different editors, instrument/drum track policies, and actual user-submitted challenging files.
- Manual physical MIDI controller and audible speaker UAT, Wait/Seek/Loop under hardware pedal use, responsive/mobile QA and memory/performance profiling remain necessary for a polished beta.
- [F0 third-party rights audit](LAUNCH-01-UPSTREAM-LICENSE-AUDIT.md) remains **BLOCKED**: owner-authorized PianoMotion integration is not a license grant for adapted upstream Hand-thesia code. A public beta must not be described as rights-cleared until documented permission, a compatible source license, or independent replacement is available.
- No expert pianist panel is required before a functional beta; generated fingering remains **opt-in and marked as unverified**.
